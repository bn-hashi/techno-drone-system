以下は、**「DOROBYそのものを丸ごとコピーする」ためではなく、公開情報をもとに、登録講習機関向けの“同等コンセプトの業務管理UI”をAIに作らせるための要件メモ**として整理します。UIデザイン・文言・画面構成・ロゴ・商品名まで完全模倣すると権利面のリスクがあるので、**機能要件・業務フロー・データ項目を参考にして、独自UIとして設計**する前提が安全です。

DOROBYの事務管理機能は、公式ページ上で「入学申込フォーム、入学者管理、受講者管理、収受記録、電子講習記録簿、シラバス、修了証明書自動生成、CSV自動生成、修了証明書発行台帳、実施状況報告書、受講規約管理、キャンペーン管理、監査向け保存資料不足一覧」などを含むとされています。スクール管理側には「四半期実施計画、管理者研修、講師研修、修了審査員研修、飛行許可承認書、定期点検、監査報告書、登録申請書・事務規程の文書管理、本社側監査資料提出」などが挙げられています。([リーガライト行政書士法人][1])
eラーニング機能は、「一等・二等、初学者・経験者のフルコース」「アカウント発行数無制限」「アカウント有効期間無制限」「進捗管理／受講期限通知」「電子講習記録簿連動」「学科修了試験システム＋230問以上」「監査資料ダウンロード」「採点結果確認」「実施状況報告書作成」「受講生専用質問フォーム」などが公開されています。([リーガライト行政書士法人][2])

# 1. 全体コンセプト

* 登録講習機関向けの事務管理システム

  * 登録講習機関の受講生・講習・修了審査・証明書・帳簿・監査資料を一元管理する
  * 学科講習、実地講習、修了審査、身体・本人確認、受講契約、収受記録、修了証明、CSV連携を管理する
  * 年次監査、オンライン監査、実地監査に必要な資料を、日常業務の入力から自動生成・整理できるようにする
  * 紙、Excel、Googleスプレッドシート、PDF、メール、手入力で分散しがちな業務を、1つの管理画面に統合する
  * 「受講生管理」「講習管理」「修了管理」「帳簿管理」「監査管理」「スクール運営管理」を主軸にする
  * 管理者、講師、修了審査員、事務担当、受講生、監査担当など、権限ごとの画面を分ける
  * 受講開始から修了証明書発行までの進捗をステータス管理する
  * 登録講習機関としての届出内容、事務規程、講習計画、講習実績が矛盾しないように警告する
  * 監査前に不足資料、不整合、期限切れ、未承認、未署名、未提出のデータを一覧化する
  * 受講者ごとの「講習記録簿」「修了証明書発行台帳」「実施状況報告書」を自動的に作れる構造にする
  * 学科・実地・修了審査の実施状況報告書を、電子講習記録簿の入力内容から自動生成する構造にする。DOROBYでも電子講習記録簿をもとに実施状況報告書が自動生成されると説明されています。([リーガライト行政書士法人][3])
  * 修了証明書の有効期間や再交付、台帳管理など、事務規程で管理すべき内容に対応できる設計にする。国交省の事務規程サンプルでも、修了証明書の有効期間や修了証明書発行台帳、講習記録簿に関する記載があります。([国土交通省][4])

# 2. 想定ユーザー・権限

* システム管理者

  * 全スクール、全事務所、全ユーザー、全設定を管理できる
  * 契約プラン、利用機能、マスタ設定、監査資料、システムログを閲覧できる
  * 権限ロールを作成・編集・停止できる
  * 事務所単位、本社単位、講習会場単位のアクセス制御を設定できる

* 登録講習機関管理者

  * 受講生管理、講習計画、講習記録、修了審査、修了証明、監査資料を管理できる
  * 講師、修了審査員、事務担当のアカウントを管理できる
  * 事務規程、登録申請書、各種変更届、飛行許可承認書などの文書を管理できる
  * 四半期実施計画書を作成・編集・確認できる
  * 実施状況報告書を確認・修正依頼できる
  * 監査用の資料不足チェックを実行できる
  * 監査報告書、不適切事項、是正措置、是正完了日を管理できる

* 本社管理者

  * 複数事務所を横断管理できる
  * 事務所ごとの講習実績、売上、収受、受講者数、修了者数、監査資料を確認できる
  * 本社側の監査資料を提出・ダウンロードできる
  * 事務所別の資料不足を一覧確認できる
  * 監査前ダッシュボードで全体リスクを把握できる

* 事務所管理者

  * 自事務所の受講生、講習、講師、会場、修了審査、資料を管理できる
  * 自事務所の四半期計画と実施状況を確認できる
  * 自事務所の監査資料をアップロード・確認できる

* 事務担当者

  * 入学申込確認、受講者登録、本人確認書類確認、請求・入金管理、案内メール送付を担当する
  * 講習日程の予約、講師アサイン、会場予約、受講生への通知を行う
  * 受講規約同意、キャンペーン適用、領収・請求・収受記録を管理する
  * 修了証明書の発行申請・出力・再発行申請を処理する

* 講師

  * 担当する学科講習・実地講習の予定を確認できる
  * 電子講習記録簿に実施内容、実施時間、受講者出欠、講習科目、補講有無を入力できる
  * 実施状況報告の入力・確認ができる
  * 自身の講師研修履歴、資格、有効期限、担当可能区分を確認できる

* 修了審査員

  * 修了審査対象者を確認できる
  * 修了審査のチェック項目、採点、減点、結果、再審査要否を入力できる
  * 修了審査員研修履歴、担当可能等級、担当可能限定変更を確認できる
  * 評価のばらつき防止に必要な記録を残せる

* 受講生

  * 入学申込フォームから申込できる
  * 受講コース、日程、支払い状況、必要書類、受講規約、案内メールを確認できる
  * eラーニング教材を受講できる
  * 進捗、期限、修了試験結果、質問フォーム、修了状況を確認できる
  * 修了証明書の発行状況を確認できる
  * 必要に応じて修了証明書再発行申請を行える

* 監査担当者・外部監査団体向け閲覧権限

  * 監査対象期間、事務所、資料カテゴリごとに必要資料を閲覧できる
  * ダウンロードされた監査資料パッケージを確認できる
  * 監査報告書、不適切事項、是正措置、期限、是正完了状況を管理できる
  * 原則、編集権限は持たず、閲覧・コメント・指摘登録のみ可能にする

* DOROBYのロゴ、配色、画面レイアウト、商品名、文言をそのままコピーしない
* 公開情報から確認できるのは機能一覧と一部の操作説明であり、内部仕様・正確なDB構造・全画面項目までは公開されていない
* ここで挙げた細かい項目は、公開情報をもとにした「同等業務を実現するためのUI要件案」
* 国交省の最新様式、登録講習機関の事務規程、監査団体のチェックリストに合わせて最終調整が必要
* 修了証明書・講習記録簿・発行台帳・CSV連携は、法令・事務規程・監査団体の要求に合わせて実装する
* 個人情報、本人確認資料、修了証明書、講習記録を扱うため、権限管理、ログ管理、ファイル暗号化、バックアップ、削除権限制御は必須
* 監査対応システムとしては「入力できる」だけでなく、「後から改ざんされていないこと」「誰がいつ編集したか」「変更理由が残っていること」が重要
* eラーニングは視聴ログ、受講時間、修了判定、試験結果、質問履歴が監査資料として説明できる状態にする
* 実地講習は天候延期、会場変更、講師変更、受講生キャンセルが多いため、計画と実績の差分管理が重要
* 受講開始から修了審査までの期限管理、修了証明書の有効期限管理、再交付管理を必ず入れる
* 将来的には、DIPS2.0や試験申込システムとの完全API連携は難しい場合があるため、まずはCSV出力・手動連携前提で設計すると現実的です。
