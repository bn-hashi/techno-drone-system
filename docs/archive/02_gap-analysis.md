## 4. UserStatusの不一致（重要）

| 既存Prisma（7状態） | デザイン表示（4状態） | 要件メモ（16状態） |
|--------------------|--------------------|----------------|
| PENDING_REGISTRATION | 申込受付 | 申込受付 |
| PENDING_ACTIVATION | 入学手続き中 | （細分化） |
| ACTIVE | 受講中（青） | 学科講習中 / 実地講習中 など |
| EXAM_PASSED | 合格 | 修了審査合格 / 不合格 / 再審査 |
| COMPLETED | 修了（緑） | 修了証明書発行済み |
| CERTIFIED | （デザインでは統合？） | CSV連携済み |
| DIPS_LINKED | （デザインでは統合？） | キャンセル / 退校 / 保留 |

**要件メモは既存7状態より多い16状態を想定しています。デザインはそれを4状態に抽象化して表示しています。**

## 5. 質問事項（ユーザーへの確認）

**必須の質問（実装判断に直結）:**

1. **フェーズ分けについて**: 上記の未実装画面のうち、今回のフェーズで実装する対象はどれですか？まず「デザイントークン統一＋ナビ刷新」だけ、という方針でも良いですか？

2. **UserStatusの扱い**: 電子講習記録簿など新機能を実装する場合、現行の7状態では不足しています。要件メモの16状態に拡張しますか、それとも現行7状態を維持してUIで吸収しますか？（DBマイグレーションが必要になります）

3. **新マスタ（講師・会場・機体）の優先度**: `VideoSupervisor` モデルは既存ですが、「講師」を独立したロール・画面として実装しますか？それとも今回はスコープ外ですか？

4. **監査機能の法令確認**: 電子講習記録簿と監査資料管理は登録講習機関の法令要件と直結します。要件メモは「確定した法令仕様ではない」とのことでしたが、これらを実装する場合、参照すべき公式仕様書はありますか？

5. **ダッシュボードのバリアント**: デザインに3種類のダッシュボードレイアウト（A/B/C）があります。どれを採用しますか、それとも独自に設計しますか？
