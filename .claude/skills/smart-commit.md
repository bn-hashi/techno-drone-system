# /smart-commit

現在のステージング状況 (`git status`, `git diff --staged`) を確認し、
変更を**論理的な単位に分割**してコミットしてください。

## 手順
1. `git status` と `git diff` で全変更を把握する
2. 変更を以下の観点で論理的にグループ化する
   - 機能追加 / バグ修正 / リファクタ / ドキュメント / テスト / 設定 を混在させない
3. グループごとに `git add <file>` でステージし、Conventional Commits 形式でコミットする

## コミットメッセージ規約 (Conventional Commits)
- `feat:` 新機能
- `fix:` バグ修正
- `refactor:` 動作を変えないリファクタ
- `test:` テスト追加・修正
- `docs:` ドキュメント
- `chore:` ビルド・設定など
- `perf:` パフォーマンス改善

## 例
- feat: ユーザーログインフォームを追加
- fix: ボタンの色を仕様通りに修正
- docs: README にセットアップ手順を追記

## ルール
- 1 コミット 1 目的を厳守
- メッセージは日本語、命令形、72 文字以内
- 関連しない変更は絶対に同じコミットに含めない
- コミット前に必ず内容を要約してユーザーに確認を取る
