# Lessons Learned

> セッション中の失敗・手戻りから得た再発防止ルール。同じミスを繰り返さないために更新し続ける。

## E2E テスト

- **状態遷移を伴う E2E はリトライ耐性を持たせる**: 試験合格→証明書発行のように
  ユーザーステータスを進めるテストは、Playwright のリトライ時に前回試行の状態が
  DB に残って失敗する。spec 冒頭で状態リセットヘルパを呼び、既知の初期状態から
  開始する（`e2e/fixtures/exam-state.ts` 参照。2026-07 に実際にこの失敗が発生）。
- **`test.describe.serial` とモジュールスコープ変数の状態共有は併用しない**:
  リトライ時にシリアルグループ全体が先頭からやり直されるため、テスト間の変数
  受け渡しが壊れる。状態遷移フローは 1 つの自己完結テストにまとめる。
- **Page Object の `toHaveURL` 正規表現は静的ルートへの誤マッチに注意**:
  `/flight/plans/[^/]+$/` は `/flight/plans/new` 自体にもマッチし、誤った
  `planId="new"` を後続に渡す。negative lookahead（`(?!new$)`）で除外する。
- **サーバー側で PDF 実レンダリングを行う API は expect のタイムアウトを延長する**:
  フォント埋め込みレンダリングは数十秒かかる。既定 5 秒では不足（証明書発行 E2E
  で 120 秒に設定）。
- **dev server は長時間稼働で劣化する**: フォーム送信後の応答が 20 秒超になったら
  テストや実装を疑う前にポート 3000 のプロセスを再起動して切り分ける。

## AI レビュー運用

- **CodeRabbit には時間あたりのレビュー数上限がある**: 短時間に複数 PR を作ると
  制限に達し、レビューは自動再開されない。次のウィンドウで `@coderabbitai review`
  を明示的にコメントして再要求する。マージ判断はレビュー完了（指摘ゼロ含む）を
  確認してから行う。

## 設定・環境

- **DATABASE_URL 等の接続先を Makefile やスクリプトにハードコードしない**:
  環境差異（本番 ubuntu / ローカル Mac / CI）で壊れるうえ、`make e2e` への開発 DB
  注入は E2E 専用 DB の fail-closed ガードを迂回させる。環境変数優先の既定値
  （Make の `?=`）を使う。
- **`.next/types` の残骸で `tsc --noEmit` が落ちることがある**: ブランチ切替で
  ページが消えた場合など。`npm run build` で再生成すれば解消する（実ファイルの
  エラーと混同しない）。
- **`npx <tool>` はグローバルキャッシュ版を解決することがある**: 再現性が必要な
  ツール（ts-node 等）は devDependencies に宣言し `node_modules/.bin/` を明示する。
